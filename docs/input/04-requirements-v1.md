# 友人向け天中殺試作 要件定義 v1

作成日: 2026-10-16。対象は[試作案v3](03-refined-plan-v3.md)。有料商品の要件は含まない。この文書を完成させても、実装と配信と友人へのURL共有は許可されない。

## 1. 承認基準

| 項目 | 内容 |
|---|---|
| 参照 | [試作案v3](03-refined-plan-v3.md) |
| 承認 | 2026-10-16の会話。CEO発言「OK。それで一旦要件定義書を作成しとこうか。」 |
| 承認に含まない | [事業案v2](03-refined-plan-v2.md)の購入場面、価格、販売、発信 |
| 目的 | 2026-10-16の飲み会で友人が自分の天中殺の種類と自己理解の短文をその場で読む |
| 成功 | 生年月日を入れると6種類の一つが出て、結果を声に出して約60秒で読める。渡す前の照合例と判定が一致する |
| 成功に含めない | 支払い、登録、公開からの訪問、事業需要の証明 |

## 2. 利用者と場面

利用者はCEOの友人である。支払者はいない。運営はCEO一人が行い、問い合わせ窓口は置かない。

利用の流れは次のとおりである。CEOがその場でURLを見せる。友人はスマホのブラウザで開き、生年月日を入れる。結果を読み、隣の人への問いを口に出す。インストール、アカウント、決済はない。

生年月日は飲み会で聞き取りやすい暦日だけを使う。生まれた時刻は聞かない。

## 3. 提供範囲

最初の試作で提供するもの。

- 入力した暦日から、日柱の旬に対応する天中殺6種類の一つを表示する
- 種類ごとに先に書いた短文を表示する。項目は後述の5つ
- 呼び名は任意。空なら種類名だけで結果を出す

提供しないもの。

- 年運、月運、大運の天中殺期間。二重天中殺を含む
- 相手の生年月日を使う相性
- 年柱、月柱、十大主星、従星、宿命中殺、日座天中殺
- 課金、LINE、メールアドレス、アカウント、結果の保存
- 鑑定士による個別鑑定、専門家資格の表示
- 生年月日を外部のAIやサーバー側の処理へ送ること

有料の一人分レポート、時期の天中殺、相性は後の候補であり、この文書の対象外である。

## 4. 業務

集客、申込、審査、決済、返金、解約は行わない。CEOが飲み会の席でURLを開かせる。不具合や判定の不一致があった場合、CEOがその場で利用を止める。

人が事前に書くのは6種類の本文である。日付から種類を選ぶ処理は自動とし、本文の生成は自動にしない。

支出は0円を仮定する。有料の配信やドメインが必要になった場合、実装の前にCEOが別途承認する。この要件はその支出を承認しない。

## 5. 機能と情報

### 画面

画面は二つである。

入力画面は年、月、日を必須とし、呼び名を任意とする。操作は「見てみる」一つ。時刻の入力欄は置かない。

結果画面の項目は次の5つであり、この順に出す。

1. 種類の名前と、薄くなりやすい側と意識が向きやすい側を含む一文
2. 人との距離。薄くなりやすい縁を2行、意識が向きやすい縁を2行
3. 今夜の場面。その種類が飲み会で出やすい反応を一つ
4. 隣への問い。当てる文を置かず、本人が答える問いを一つ
5. 注記。暦日だけを見ていること、日付の境目は見ていないこと、算命学の一つの見方で時期の吉凶ではないこと

結果はスマホの幅で横スクロールせず、声に出して約60秒で読み終わる長さにする。

### 計算

日本の暦日として扱う。日付の変わり目は午前0時とし、23時で日付を変える方式は使わない。生まれた時刻は計算に入れない。

日柱の六十干支を求め、次の旬と種類の対応で一つに決める。対応の出典は占術ラボの公開説明（2026-08-06更新、2026-10-16閲覧）である。六十干支を10個ずつの旬に分け、干が届かない2支を天中殺とする。四柱推命の空亡と同じ算出構造である。

| 旬 | 日柱の範囲 | 表示する種類 |
|---|---|---|
| 甲子旬 | 甲子〜癸酉 | 戌亥天中殺 |
| 甲戌旬 | 甲戌〜癸未 | 申酉天中殺 |
| 甲申旬 | 甲申〜癸巳 | 午未天中殺 |
| 甲午旬 | 甲午〜癸卯 | 辰巳天中殺 |
| 甲辰旬 | 甲辰〜癸丑 | 寅卯天中殺 |
| 甲寅旬 | 甲寅〜癸亥 | 子丑天中殺 |

日柱の支が天中殺2支に含まれる組み合わせは構造上ない。60通りの照合でこの条件を満たす。

### 本文の軸

6種類の本文は欠けやすい縁と、その反対に意識が向きやすい縁の対で書く。性格の長文は自作し、他サイトの文章を転載しない。次の対は占術ラボの通俗的な要約を軸にしたものである。流派で力点は変わる。注記でその旨を示す。

| 種類 | 薄くなりやすい側 | 意識が向きやすい側 |
|---|---|---|
| 子丑天中殺 | 父、先輩、上司など目上 | 子供、後輩、部下など目下 |
| 寅卯天中殺 | 母、友人、兄弟など横のつながり | 配偶者、家庭 |
| 辰巳天中殺 | 精神的な分かち合い | 現実での実行 |
| 午未天中殺 | 子供、後輩、部下など目下 | 父、先輩、上司など目上 |
| 申酉天中殺 | 配偶者、家庭 | 母、友人、兄弟など横のつながり |
| 戌亥天中殺 | 現実での実行 | 精神的な分かち合い |

時期の吉凶、禁止事項、「このままでは」という不安の文は書かない。

### データ

生年月日と呼称はブラウザ内だけで使い、サーバー、ログ、外部AIへ送らない。ページ本体の取得を除き、生年月日を含む通信を発生させない。保存期間はページを閉じるまでとする。同意画面は保存しないことをもって省略する。

URLを知っている人はログインなしで使える。検索エンジンへの掲載はしない。公開の宣伝はしない。

技術の製品名は固定しない。友人のスマホのブラウザで追加インストールなしに開ければよい。開いたあとの判定は端末内で完結させる。

### 状態

未入力では結果を出さない。存在しない日、欠落した年月日では結果を出さず、入れ直しを求める。正常時は6種類のうち一つだけを出す。同じ暦日なら、ページを開き直しても同じ種類と同じ本文になる。

## 6. 品質と制約

応答はページを開いた後の判定を待ち時間なしで表示する。通信先で文章を生成しない。

可用性の対象は2026-10-16の飲み会の間である。24時間の運用と監視は要件にしない。

個人情報は生年月日と呼称である。今回は保存しないことで扱う。有料化する場合の説明、同意、保存期間は別要件で決める。Q-07の商用条件は未決のままである。

算出は日柱の旬に限る。海外出生地、サマータイム、節入り、23時境界は見ない。この限定を注記に書く。商用の暦条件はQ-09として未決のままである。

法務の判断は次のとおり分ける。この試作は不安をあおる時期表現を置かない。有料販売、特定商取引法、霊感商法に関する確認は販売要件の前に行い、公式情報と必要なら専門家の確認を取る。今回の文書ではその確認を完了扱いにしない。

CEOの算命学の学習歴と監修者は未確認である。画面に専門家、鑑定、資格を表示しない。

## 7. 計測

計測用のアクセス解析と、生年月日が残るログは置かない。

CEOは任意で使った人数と、声に出して最後まで読めたかどうかだけをメモしてよい。生年月日、呼び名、感想の原文、購入意向はメモしない。友人の「当たっている」は需要の証拠にしない。

担当はCEOである。費用の記録対象は支出0円、または別承認した配信費の実額である。継続と失注は販売がないため記録しない。

## 8. 優先順位と受け入れ条件

| 要件ID | 要件 | 根拠 | 優先度 | 受け入れ条件 |
|---|---|---|---|---|
| REQ-01 | 年・月・日だけを必須入力にする | 試作案v3。時刻は飲み会で揃わない | 必須 | 時刻欄がない。空欄と存在しない日では結果が出ない |
| REQ-02 | 日柱の旬から6種類の一つを出す | H-04。渡す前に計算が合うこと | 必須 | 上表の6旬がすべて一致する。60通りで日支が天中殺2支に含まれない。公開の万年暦と照合した生年月日の例が期待する日柱と種類に一致する |
| REQ-03 | 結果を5項目、約60秒で読める長さにする | 試作案v3 | 必須 | 種類の一文、人との距離4行、今夜の場面一つ、隣への問い一つ、注記3点がこの順で表示される |
| REQ-04 | 6種類の本文を事前に書き、対の軸で揃える | 試作案v3。転載回避（Q-10） | 必須 | 同じ日は同じ文になる。通信で本文を生成しない。他サイトの文章の転載がない。上表の対から外れた縁を主軸にしない |
| REQ-05 | 生年月日を端末内だけで扱う | Q-07の試作限定 | 必須 | ページ取得以外に、生年月日を含む通信がない。結果をサーバーに保存しない |
| REQ-06 | 友人のスマホのブラウザで開く | 飲み会の利用場面 | 必須 | 追加インストールなしで開ける。localhostだけを渡す状態では完了にしない |
| REQ-07 | 時期の天中殺、相性、星一覧、課金、アカウントを出さない | 試作案v3。不安喚起を避ける | 必須 | それらの入力、表示、導線がない |
| REQ-08 | 専門家表示と需要の数え方を分ける | Q-01未確認。友人の感想を購入に数えない | 必須 | 資格、鑑定、監修済みの表示がない。計測が人数と読了の任意メモに限られる |
| REQ-09 | 呼び名を任意表示する | 試作案v3 | 後回し | 入力があれば結果の見出しに出る。空でもREQ-03を満たす |
| REQ-10 | 有料レポート、相性、時期判定 | 事業案v2は未承認 | 対象外 | この文書の実装範囲に機能を増やさない |

完了の確認者はCEOである。REQ-02の照合表は友人にURLを渡す前に手元へ残す。不一致が一つでもあれば渡さない。

## 9. 開始、停止、未決

実装、配信、友人への共有は別の明示承認があるまで開始しない。

停止条件は次のどれかである。照合例と判定が一致しない。生年月日が端末の外へ出る。結果に時期の吉凶や相性が入る。飲み会の前にREQ-02と本文の確認が終わらない。

| ID | 未決 | 影響 | 決め方と時期 |
|---|---|---|---|
| U-01 | 配信先 | 友人のスマホから開けない | 実装を承認するときにCEOが選ぶ。有料ならその時点で費用も承認する。飲み会の前 |
| U-02 | 照合する生年月日と期待する日柱 | REQ-02を確認できない | 実装着手時に、公開の万年暦から例を取り、渡す前に照合する |
| U-03 | 6種類の最終文面 | 読んだときの中身が変わる | 渡す前にCEOが6種類を読む |
| U-04 | 有料商品の購入場面、一人分か相性か、価格 | 事業案v2の要件が作れない | この試作の感想では決めない。Q-05、Q-13、Q-14として残す |
| U-05 | 学習歴、監修、販売主体、予算 | 商用提供の責任範囲 | [未決事項](05-open-questions.md)のQ-01からQ-04、Q-06。試作の画面では未確認のまま専門性を表示しない |

U-01からU-03はこの要件定義書の完成条件に含めず、友人に渡す実装の条件とする。
