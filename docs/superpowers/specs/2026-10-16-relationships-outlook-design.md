## 目的と画面

2026-10-16の追加要望を反映。目的は「算命学を活用した自己分析サイト」である。短い性格分類を表示する試作から、読んだ人が経験・選択・関係性を振り返れる結果へ広げる。読む長さは5〜10分程度を目安とし、1結果の可視本文は3,500〜5,000字を編集上の目標にする。読む速さには個人差があるため時間を保証しない。

従来の約60秒、短い定型文、結果5ブロック、本文を変えないという制限は、情報量を増やす今回の指示に従って変更する。日柱の基準日・計算、個人情報の扱いは変えない。既存の一文は導入として使えるが、その一文だけを概要にしない。芸能人3人は最後の短い補足に残す。

結果は次の順で読む。全章を1列に置き、冒頭に章へのリンクを設ける。長文を小さな文字で詰めず、各章を複数の段落と小見出しに分ける。全文を初期表示し、読むために開閉操作を必須にしない。生成り・墨色・朱色の見た目を引き継ぎ、320px幅で横スクロールしない。

## 文章の制作基準

- 「親より子どもを大事にする」「友人の話を聞き流す」といった単純な優劣や失礼な行動の決めつけを中心に置かない。
- 「縁が薄い」を、愛情がない、不仲になる、親を頼ってはいけないという意味へ飛躍させない。「縁が強い」も、必ず支援や成功が得られるという保証にしない。
- 自由、独立、継承、専門性などの意味を、職場・学び・恋人・身近な人との具体的な場面に置き換える。
- 長所だけを並べない。同じ傾向が負担になる場面と、それを調整する行動を対にする。
- 読み手の過去や家庭の事情を言い当てたように書かない。占術上の読み方、日常への解釈、本人への問いを分ける。
- 6種類すべてに固有の概要と具体例を書く。同じ文章の種類名だけを変えない。

概要の密度を確かめる本文案を `docs/superpowers/specs/2026-10-16-self-analysis-copy-sample.md` に置く。算命学の基本的な読み方を日常へ広げる部分は、原典の逐語訳や学説そのものとして扱わず、本アプリの編集文として明示する。

## 入力方式の提案

現時点の提案は本人1人の入力で完結する方式。相手の特徴と関わり方を示す。相手の生年月日を入れて2人を比較する機能は含めない。2026-10-16の「OK」「進めて」で、この方式を含む設計と本文密度の確認を得た。

性別や年齢で恋愛対象を決めない。相性の点数、成功率、特定の天中殺同士の優劣は作らない。6種類だけから二人の総合相性を判断できるとは説明しない。既存の人物像をもとにした本アプリの提案として文章を作る。

恋愛・仕事それぞれに、相手の特徴を表す一文、日常の行動例2つ、自分が意識する関わり方1つを出す。同じ内容を恋愛と仕事で使い回さない。上の字数と内容の基準に沿って、短い行動例だけで終えず、理由と関係の育て方まで説明する。

| 種類 | 恋愛の相手像 | 仕事の相手像 |
|---|---|---|
| 子丑 | 応援や相談を一方通行にせず、自分からも支える人 | 任せる範囲を決め、必要な時に相談できる人 |
| 寅卯 | 二人の生活や予定を具体的に話し合える人 | 落ち着いて継続できる段取りを作る人 |
| 辰巳 | 気持ちを伝えたうえで、一緒に次の行動を決める人 | 目的と期限を共有し、小さく試す人 |
| 午未 | 敬意を持って接しながら、対等に意見を伝える人 | 判断の基準を説明し、仕事の進め方を相談できる人 |
| 申酉 | 友人や一人の時間を尊重し、二人の約束も守る人 | 情報を共有し、得意分野で役割を分ける人 |
| 戌亥 | 結論を急がず気持ちを聞き、約束も言葉にする人 | 意図を確かめてから、段取りを形にする人 |

例・子丑の恋愛：相手像のあとに「相談を聞くだけでなく、あなたの話も聞く。困った時には、頼まれる前に声をかける。」を置く。自分への提案は「頼られるだけの関係にせず、自分からも小さなお願いを伝える。」とする。これは算命学の定理の引用ではなく、既存の人物像をもとに書く編集文である。他の種類も同じ粒度で制作する。

## 3年間の範囲

提案は表示時点の日本時間の暦年と、その翌年・翌々年。2026年に開けば2026・2027・2028年を表示する。2026年に固定しない。入力された生年月日の年を開始年にしない。

3年間の見出しの下に「日干と年の干支による、過ごし方の目安。」と表示し、命式全体を読む総合鑑定だと誤認させない。これは今回の追加設計で提案する表示であり、従来の注記を出さない指定からの変更として確認する。

各カードは「2026年」のような西暦、テーマの一文、その年の説明、取り組むこと2つ、気をつけること1つを持つ。期間は各年の立春から翌年の立春前日までと表示する。暦年1月1日と占術上の年の切り替えを混同しない。特定の日の立春時刻や、今日が天中殺の中かという判定は今回の対象外とする。

## 年ごとの計算と文章

生年月日から求めた日干と、表示対象年の年干の関係を年のテーマへ対応させる。年の干支は1984年を甲子として60年で循環する。陰陽と五行の関係から十大主星のうち一つを内部で求める。命式全体や大運を使った総合的な年運とは区別する。星の一覧や命式の表は画面に追加しない。

| 日干から見た年干 | 陰陽が同じ | 陰陽が違う |
|---|---|---|
| 同じ五行 | 貫索：自分の軸を固める | 石門：人とつながる |
| 日干が年干を生じる | 鳳閣：経験を言葉にする | 調舒：自分の表現を磨く |
| 日干が年干を剋す | 禄存：人に働きかける | 司禄：日々の積み重ねを育てる |
| 年干が日干を剋す | 車騎：手を動かして進める | 牽牛：役割と約束を整える |
| 年干が日干を生じる | 龍高：新しい経験から学ぶ | 玉堂：学びを深める |

各テーマの説明・行動例・注意点は本アプリ用の編集文である。出来事の発生、収入、結婚・転職の成否を保証しない。「必ず成功する」「結婚してはいけない」のような断定を避ける。

さらに、年支が本人の天中殺の2支に含まれるかを計算する。該当する年は「天中殺に当たる年」と明記し、そのテーマについて棚卸し、学習、余白作りを優先する文章へ切り替える。該当しない年を自動的に幸運と呼ばない。

確認例：2000-01-01は戊午・子丑天中殺。2026丙午は龍高、2027丁未は玉堂、2028戊申は貫索で、3年とも年運天中殺に当たらない。午未天中殺の人は2026・2027年に該当し、2028年は該当しない。

## データと境界

計算と文章選択は端末内で完結する。年の計算は独立した純関数にし、UIから表示時点の年を渡す。本文は固定の定数とし、表示時にAIを呼ばない。新しい依存パッケージは不要。生年月日をURL、保存領域、fetch、外部AIへ出さない。

追加候補ファイルは `src/content/relationships.ts`、`src/domain/outlook.ts`、`src/content/outlook.ts` とそれぞれのテスト。UIは `src/ui/app.ts` と `src/style.css` を拡張する。

テストは6種類の恋愛・仕事の内容が別々に選ばれること、日干10通りと年干10通りの対応、干支60年周期、年支12通りと天中殺6種類の判定、上の公開暦日を使った期待値、年越し、日本以外のタイムゾーン、上記の章の順序、再入力で新しい内容も消えること、送信・保存しないことを固定する。ブラウザでは3年分の長文と長い見出しをスマホ幅で確認する。
